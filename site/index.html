NEAR HACKATHON · Investment Thesis

Is NEAR already a payments rail?

If NEAR is becoming money infrastructure, its stablecoins should move like payments: many small transfers between ordinary wallets, a steady daily rhythm, and no dependence on NEAR's price swings. If it is mostly a trading venue, the flow runs through DEXs and bots and follows volatility. We pulled USDC and USDT transfers straight from NEAR mainnet blocks over days and checked them against six tests written down first.

    06 · Method

    How the numbers were made

    Method

    • Tokens: native USDC (17208628…33a1, Circle), native USDT (usdt.tether-token.near, Tether) and the Rainbow Bridge versions USDC.e / USDT.e.
    • Sample: for each UTC day we draw a fixed number of block heights at random (seed 20261114) and download the full block from neardata.xyz. Every successful NEP-141 transfer, mint and burn from these contracts is kept.
    • Estimates: day total = sample total × blocks in day ÷ sampled blocks. 95% intervals: 300 block-level bootstrap resamples.
    • Counterparty type: documented labels first, then a code check (does the account have a contract deployed?). Wallet-to-wallet means neither side has code.
    • Rebuild everything: make all (Python 3 standard library only, no API keys).

    Limitations

    • It is a sample ( of blocks), not a census. Unique-user counts are not estimated because a block sample cannot measure them.
    • Exchange hot wallets are not labeled unless documented; they show up as wallets or contracts. A wallet-to-wallet transfer can still be a trader moving funds.
    • Transfers into NEAR Intents can be cross-chain payments, not only swaps. We count them as trading-venue flow, which is the conservative choice for this thesis.
    • Amounts are taken at $1 per token. Window: .
